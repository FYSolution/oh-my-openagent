# R5: per-user web-cache for web_search (status: implemented)

Fifth and final increment. Scraped web content is per-user, volatile, and
license-encumbered, so it is explicitly OUT of the committed wiki — it is
memoized on disk under `.omo/web-cache/` with a TTL, never promoted to a
fragment automatically. A human still has to lift durable web-derived insight
into a normal `trust: source` fragment by hand. OFF by default.

## Cache core

`packages/omo-opencode/src/tools/web-search-local/web-cache.ts` — a small
`WebCache` class (no OpenCode dependency beyond the shared logger):

- `computeKey({ query, goal, maxPages, maxDepth })` -> 32-hex SHA-256 of the
  normalized (trimmed, lowercased) inputs. Same inputs -> same key; different
  crawl breadth -> different key.
- `get(key)` -> `CrawlResult | null`; returns null on miss, and on a stale entry
  it evicts the file and returns null (TTL = `now - cachedAt > ttlMs`).
- `set(key, query, goal, result)` -> atomic write (temp file + rename) of a
  `WebCacheEntry { trust: "source", cachedAt, query, goal, result }`.
- Injectable `now` for deterministic tests; all fs failures are logged, never
  thrown (a broken cache must never break a search).

`createWebCache(directory, ttlMinutes, now?)` resolves the dir to
`<directory>/.omo/web-cache/`.

## Wiring

- `LocalWebSearchToolOptions` gained an optional `cache?: WebCache`. In
  `tool.ts` the tool computes the key, returns the formatted cached
  `CrawlResult` on a hit (reusing the canonical `formatWebSearchResult`, so
  cached and live output are byte-identical), and on a miss stores the result
  only when it has >0 results.
- `createWebSearchToolsRecord` builds the cache from
  `websearch.local.cache.{enabled, ttl_minutes}` (default TTL 60 min) and passes
  it in. Cache only exists when `prefer_local === true` (the local `web_search`
  tool is the only cached path; the remote Exa MCP path is untouched).

## Config

`websearch.local.cache` (new `WebCacheConfigSchema`): `enabled` (default false)

- `ttl_minutes` (min 1, default 60). Regenerated into
  `assets/oh-my-opencode.schema.json`.

## Validation & remaining gate

5 new cache tests green; 145 pass across the websearch + registry + config
suites (no regressions); tsgo clean; schema regenerated.

`opencode-qa` (drive real OpenCode, prove a second identical `web_search` hits
the cache) remains the outstanding merge gate for R2 + R3 + R4 + R5 — it cannot
run in the Windows VS Code environment.

## Deliberately not done (scoped out)

- The `websearch-local-redirect` hook path (Exa -> local fallback) is not
  cached; only the direct `web_search` tool is. A follow-up could thread the
  same `WebCache` through that hook.
- No auto-promotion of cached content into wiki fragments — by design, promotion
  is a human step.
