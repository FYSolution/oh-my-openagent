# Deploying the Second_Brain-enabled build to OpenCode 1.17.13

## Plugin resolution changed in opencode-ai 1.17.13

opencode self-upgrades via npm. Version 1.17.13 (installed `2026-07-02T00:09:11Z`) no longer
resolves a bare plugin name. `"plugin":["oh-my-openagent"]` is silently ignored: the managed
package store `~/.cache/opencode/packages` is empty, the implicit install fails silently, and
`opencode.log` shows no plugin-load step at all (config load -> LSP -> session -> loop). The omo
log (`%TEMP%\oh-my-opencode.log`) does not grow and the session falls back to the built-in
"build" agent with built-in WebFetch.

## Working local-dev deployment

Reference the built file directly by `file://` absolute path in `~/.config/opencode/opencode.json`:

```json
{ "plugin": ["file:///C:/MyWorkplace/fy_solution/oh-my-openagent/dist/index.js"] }
```

No sandbox copy is needed — opencode imports the workspace `dist/index.js` in place. Build with
`bun build packages/omo-opencode/src/index.ts --outdir dist --target bun --format esm --external zod --external playwright-core`
and ensure `dist/skills/*/SKILL.md` exist (`bun run build:shared-skills-assets`), because the
bundle reads them at import time and a missing skill dir makes the plugin fail to load silently.

## Enabling R6 auto-init

Auto-init is double-gated: it runs only when `second_brain.enabled:true` AND
`second_brain.auto_init:true`. Both absent -> no scaffold (correct). To turn it on, add to
`~/.config/opencode/oh-my-openagent.json`:

```json
{ "second_brain": { "enabled": true, "auto_init": true, "inject_context": true } }
```

On the next session start in a project without a `Second_Brain/`, the plugin scaffolds one
(`SCHEMA.md`, `.gitignore`, `raw/code-updates/`, `wiki/fragments/{user}/getting-started.md`,
`wiki/log/{user}/{date}.md`, `wiki/.compiled/_manifest.json`) and logs
`[second-brain-init] Scaffolded Second_Brain`. The user defaults to `SECOND_BRAIN_USER` or "user".
