# R6 follow-up: auto-init MERGES into an existing (old-version) Second_Brain

Supersedes the earlier "No-op (`created: false`) when `root` already exists" behavior of
`scaffoldSecondBrain`. Initing into a solution that already has an old Second_Brain no longer
skips it — it reconciles the missing pieces. Still OFF by default (`enabled` + `auto_init`).

## Scaffolder is now merge-capable

`packages/second-brain-core/src/scaffold.ts` — `scaffoldSecondBrain(root, { user?, now? })`
now returns `{ created, merged, root, added[] }`:

- `created: true` only when `root` was absent and freshly created.
- `merged: true` when `root` existed and >=1 missing piece was added.
- `added` — root-relative paths of everything written this call.

Per-piece ensure (never overwrites existing content):

- Missing dirs: `wiki/fragments/{user}`, `wiki/log/{user}`, `raw/code-updates`.
- Absent top-level files: `.gitignore`, `SCHEMA.md`.
- SCHEMA content merge is heading-additive — a starter `##` section is appended only when
  its heading is absent (`mergeSchemaSections` / `splitSchemaSections` / `normalizeHeading`).
  Existing sections are byte-preserved. The `added` marker is `SCHEMA.md#sections`.
- Starter `getting-started` fragment + daily log are seeded ONLY into an empty user space
  (`hasMarkdown` guard) so an established brain is never polluted.
- Always `rebuildIndex(root, { persist: true })` so `.compiled/_manifest.json` is current.

## Auto-init wiring

`packages/omo-opencode/src/tools/second-brain/auto-init.ts` dropped the early
`existsSync(root)` no-op; it now always calls the scaffold, logs
`Merged missing pieces into existing Second_Brain` (with `added`) on the merge path, and
returns `created || merged`.

## Config-block merge (the real gap)

`packages/omo-opencode/src/plugin-config/config-merger.ts` now `deepMerge`s the
`second_brain` block across config layers. Previously it was spread shallow via `...override`,
so a project-layer `second_brain` fully REPLACED the user layer's block (dropping fields like
`auto_init`). `deepMerge` tolerates `undefined` on either side, so the block stays undefined
when neither layer sets it.

## Detection / policy

- Old-version detection is structural (missing expected files/dirs); no version marker.
- Never-overwrite: merge only ADDS; it never rewrites existing files or SCHEMA sections.
- The scaffold never edits the user's `.opencode/*.jsonc` — config-block reconciliation is a
  loader concern (`mergeConfigs` deepMerge), not a file rewrite.

## Tests

- `scaffold.test.ts`: partial-brain merge + additive SCHEMA merge + never-overwrite preserved.
- `auto-init.test.ts`: existing-brain case is now a merge; complete brain merges nothing.
- `config-merger.second-brain.test.ts`: layered `second_brain` deep-merge + stays undefined.
