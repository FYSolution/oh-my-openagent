# R6: auto-init / scaffold Second_Brain into a project (status: implemented)

Sixth increment (beyond the original R1-R5 plan). Answers "if a project has no
Second_Brain, can oh-my-openagent generate it?" — now yes, without the client
setting it up by hand. OFF by default (needs both `enabled` and `auto_init`).

## Scaffolder core

`packages/second-brain-core/src/scaffold.ts` — pure fs + string templates, no
OpenCode dependency, idempotent:

- `scaffoldSecondBrain(root, { user?, now? })` -> `{ created, root }`.
- No-op (`created: false`) when `root` already exists — never overwrites.
- Normalizes `user` (lowercase, spaces -> hyphens, empty -> `"user"`).
- Creates `wiki/fragments/{user}/`, `wiki/log/{user}/`, `raw/code-updates/`.
- Writes `.gitignore` (ignores `wiki/.compiled/`), a minimal `SCHEMA.md`, a seed
  `type: overview` "getting-started" fragment, and a seed daily log.
- Calls `rebuildIndex(root, { now, persist: true })` so `.compiled/_manifest.json`
  exists immediately (regenerated in TS — the scaffold does NOT ship the pwsh
  authoring scripts, keeping it cross-platform).

## Adapter + gating

`packages/omo-opencode/src/tools/second-brain/auto-init.ts` —
`maybeAutoInitSecondBrain(directory, config)`:

- Returns false unless `second_brain.enabled === true && auto_init === true`.
- Resolves root = `config.path ?? <directory>/Second_Brain`; no-op if it exists.
- Resolves `user` from `SECOND_BRAIN_USER` env (default `"user"`).
- All scaffold failures are caught and logged — a broken scaffold never breaks
  plugin startup.

## Wiring

Called once at plugin startup in
`packages/omo-opencode/src/testing/create-plugin-module.ts`, immediately after
`loadPluginConfig` — i.e. "when opencode is used in the solution folder". Single
non-branching statement (kept `serverPlugin`'s complexity unchanged).

## Config

`second_brain.auto_init` (new boolean, default false). Regenerated into
`assets/oh-my-opencode.schema.json`.

## Safety rationale

Writing ~5 files + folders into a client repo is a real side effect, so it is
double-gated behind two explicit opt-ins rather than firing on `enabled` alone.
Idempotent + failure-safe: safe to run on every startup.

## Validation & remaining gate

8 new tests (4 scaffold core, 4 adapter gating) green; 161 pass across
second-brain-core + plugin-module + config suites (no regressions); tsgo clean
on both packages; schema regenerated.

`opencode-qa` (drive real OpenCode in a folder with no Second_Brain and observe
the scaffold appear) remains the outstanding merge gate for R2-R6 — it cannot
run in the Windows VS Code environment.
