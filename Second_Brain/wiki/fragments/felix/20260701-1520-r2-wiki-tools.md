# R2: `wiki_search` + `wiki_read` tools (status: implemented)

The first OpenCode-facing consumers of `second-brain-core`. Two read-only native
tools, OFF by default, that surface committed wiki memory to agents in a live
session.

## Config gate (`second_brain`)

New schema `packages/omo-opencode/src/config/schema/second-brain.ts`, registered
on `OhMyOpenCodeConfigSchema` as `second_brain` (optional). Fields kept minimal
for R2:

- `enabled` (default false) — the hard gate.
- `path` (default `<projectRoot>/Second_Brain`) — directory override.
- `search_default_top` (1-50, default 10) — default `wiki_search` result count.

Injection-side fields from the design (`inject_on_session_start`,
`max_inject_tokens`, `persist_index`) are deliberately deferred to R3/R4 rather
than shipping unused config now.

## Gating (identical pattern to web_search)

`createSecondBrainToolsRecord({ pluginConfig, ctx })` in
`tool-registry-gated-tools.ts` returns `{}` unless
`pluginConfig.second_brain?.enabled === true`, then delegates to
`createSecondBrainTools(ctx, pluginConfig.second_brain)`. Spread into the tool
map in `tool-registry.ts` right after `createWebSearchToolsRecord`. Because it is
a no-op when disabled, existing tool counts are unchanged.

## Tool surface

- `wiki_search(query, top?, folder?)` — keyword AND via `searchWiki`; returns a
  markdown table (Score, State, File, Match), freshness/trust-weighted, capped at
  `top ?? search_default_top`. `folder` restricts to a `wiki/` subfolder.
- `wiki_read(target)` — returns the assembled per-target page via `readTarget`
  (lessons/decisions excluded by that contract); falls back to a
  "try wiki_search first" hint when the target has no page.

`createSecondBrainTools` takes injectable `{ searchWiki, readTarget }` deps so the
test suite can pin a fixed clock (deterministic freshness) against the committed
`test-support/second-brain-fixtures/basic` fixture. `ctx` is typed
`Pick<PluginInput, "directory">` — no full stub, no `as any`.
