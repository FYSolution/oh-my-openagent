### Decisions

- Reason for change: pagination auto-follow previously only worked in the Playwright path; fetch-only mode (corporate default) always returned `paginationNext: null`, so DuckDuckGo/site pagination never continued there.
- Do NOT guess the next URL by string construction. Primary strategies READ the site's declared href (`rel="next"` on link/a, then next-labeled anchor inside a pagination container). Only the fallback infers `?page/?p` + 1. This keeps dynamic URL schemes (path-based, cursor, offset) working when the site declares rel=next or a labeled next link.
- False-positive control: the text/symbol anchor strategy is scoped to pagination containers (class/id/aria-label contains pagination|pager|page-nav), within a 4000-char window. A bare "next steps" prose link is NOT matched (test-verified).
- Depth: unchanged — pagination continuation is still enqueued at the SAME depth in crawl-loop, and volume stays capped by `domainPageCap=5` / `maxPages=10` (cap 15). Per request, deep (>10 sub-page) traversal was intentionally NOT added.

## [12:40] Multiline-tolerant frontmatter parser + runtime-bridge design revision

### Files Modified

- Second_Brain/scripts/compile-wiki.ps1 — `Parse-FragmentFrontmatter` now collects frontmatter lines, merges continuation lines into logical lines (a new key only starts on `^\w[\w-]*:`), then parses; flow arrays handled single- or multi-line with empty/trailing-comma elements filtered.

- Second_Brain/wiki/fragments/felix/20260701-1215-second-brain-runtime-design.md — revised per feedback (see Decisions).
- Second_Brain/wiki/fragments/felix/20260701-1240-formatter-breaks-frontmatter-arrays.md — NEW lesson.

### Root cause

A markdown/YAML formatter reflowed `code_anchors: [a, b]` into a multiline flow array. The old parser matched only `^key:\s*(.+)$` + `^\[(.+)\]$`, so a `key:` with an empty value + bracketed continuation lines was silently ignored → no anchors parsed → drift detection disabled → false FRESH.

### Decisions

- Design correction (per user): the compiled index is essential and **regenerable**. `.compiled/` is a regenerable cache with a stable contract, NOT a build artifact to avoid. `second-brain-core` (TS) becomes a second producer of that same contract: read-through cache (use `.compiled/` when fresh by mtime, else regenerate in TS, optional `persist_index` write-back). Resolved the manifest-shape open question toward pwsh/TS **parity**.
- Parse frontmatter tolerantly; never assume authored frontmatter survives a formatter.

- The system caught its own regression: the search-wiki.ps1 edit shifted the analysis fragment's anchored lines → recompile flagged it DRIFTED (line-range moved, content/hash unchanged) → re-stamped range → clean.
