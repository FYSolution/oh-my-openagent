  proving `.compiled/` copy and `README.md` are excluded.

### Decisions

- Fragments are the only searchable source of truth. `.compiled/` (gitignored/generated),
  `log/`, and `journal/` are excluded so results are deterministic across machines.
- Root cause of the bug set: over-broad `wiki/` walk pulled in compiled duplicates, which
  (a) inflated hit-count scoring, (b) had no frontmatter so ranked as `UNKNOWN` freshness,
  and (c) had no `target` so a compiled top-hit made `selectWikiContext` return null and
  suppressed auto-injection.

## [17:40] Wiki search recall: OR fallback + target/tag weighting

### Files Modified

- packages/second-brain-core/src/search.ts — new `evaluateFile` (per-keyword body hits +
  target/tag detection → `matchedCount`, `tagTargetBonus`) and `scoreOf` (base ×
  fraction × freshness × trust). `searchWiki` now evaluates every file once, keeps AND
  matches when any exist, and falls back to OR (scaled by `matchedCount/keywordCount`)
  only when AND is empty. `TARGET_MATCH_WEIGHT=6`, `TAG_MATCH_WEIGHT=3`.
- Second_Brain/scripts/search-wiki.ps1 — mirrored: two-phase candidate collection, target
  (+6)/tags (+3) weighting, OR fallback with fraction scaling; description updated.
- packages/second-brain-core/src/search.test.ts — added OR-fallback test and target/tag
  weighting test.
- Re-stamped two code anchors whose line numbers shifted from these edits (hashes
  unchanged, proving the anchored code is intact):
  - felix/20260702-1615-search-scope-fragments-only.md → search.ts#L142-L144@ae49bcb1
  - felix/20260701-1145-freshness-envelope-analysis.md → search-wiki.ps1#L142-L152@3164d572

### Decisions

- AND remains the primary mode; OR is a fallback ONLY when AND matches nothing, so
  precision is preserved for well-phrased queries while partial-vocabulary questions
  stop returning empty (which previously suppressed auto-injection silently).
- `target`/`tags` frontmatter is treated as curated synonyms and weighted above plain body
  hits.
- Known tradeoff: substring target matches can let a common embedded keyword (e.g. "search"
  in `local-web-search`) outrank a more distinctive term; it only reorders, never drops
  correct AND matches. Left for a possible future whole-word refinement.
